# API551 — правила переделки Figure от исходника и точной рамки callout

Статус: CURRENT active addendum for Stage 4+ Figure work.

Дата: 2026-07-01.

Область применения: все первичные сборки, повторные переделки, correction pass, revision pass и review-overlay пакеты для API 551 Figure objects.

Приоритет: этот файл дополняет `source/API551_CONSOLIDATED_POLICIES_and_RULES_CURRENT_2026-06-18.md` и `source/API551_UNIVERSAL_FIGURE_LABEL_CLEANUP_AND_PLACEMENT_RULES_CURRENT_2026-06-25.md`. При конфликте остановиться и показать источник, роль, конфликт и риск.

## 1. Source-of-truth для всех переделок

1.1. Любая первичная сборка Figure и любая последующая переделка / correction pass / revision pass должны выполняться от исходного PDF-derived source crop или другого чистого исходного project source.

1.2. Запрещено выполнять повторную переделку от уже переведённого PNG, прошлой review-версии, overlay-результата, ранее модифицированного `figure_*.png` или mixed/contaminated source.

1.3. Предыдущая translated/review PNG-версия может использоваться только как визуальная reference-подсказка, но не как production source для новой сборки.

1.4. Для каждого revision pass обязательно заново:

- взять clean source из оригинального PDF/source crop;
- выполнить source-text cleanup;
- рассчитать placement geometry;
- построить callout frame по фактическим границам перевода;
- проверить пересечение с protected graphics;
- пересобрать ZIP и проверить внутренний PNG из свежего extract.

1.5. Если чистый PDF-derived source crop недоступен или загрязнён, остановиться и сообщить source problem. Не маскировать загрязнённый translated PNG как будто это исходник.

## 2. Правило точной рамки для leader-line callout

2.1. Для `leader_line_callout` рамка строится от фактических границ уже отрисованного перевода в финальном экспортируемом PNG.

2.2. Внутренний зазор между реальными границами букв/цифр перевода и внутренним краем тонкой серой рамки должен составлять 3–5 px в финальном PNG.

2.3. Нельзя трактовать 3–5 px как source-equivalent, render-scale equivalent или «примерно после масштабирования». Проверяется именно финальный растровый PNG, который попадёт в ZIP.

2.4. Нельзя растягивать рамку до выносной линии, если это создаёт большие пустые поля вокруг текста. Если рамка не может одновременно иметь зазор 3–5 px и касаться выносной линии, нужно перемещать весь компактный callout-блок ближе к линии, менять переносы/размер шрифта или переводить объект в manual review.

2.5. Запрещено использовать для размера рамки:

- старый source bbox;
- cleanup bbox;
- bbox предыдущей review-версии;
- bbox старого английского текста;
- фиксированную ширину «для красоты»;
- увеличенный box только ради достижения линии.

2.6. Рамка должна касаться соответствующей выносной линии там, где это возможно без повреждения protected graphics.

2.7. Если прямое касание невозможно без пересечения/закрытия защищённой графики, допускается только минимальный безопасный зазор. Исключение обязательно фиксировать в object JSON QA notes с причиной.

2.8. При QA для каждого `leader_line_callout` фиксировать:

- фактический text bbox в финальном PNG;
- frame bbox в финальном PNG;
- padding left/top/right/bottom в px;
- отношение к выносной линии: `touches`, `minimal_safe_gap`, `manual_review`;
- отсутствие пересечения с leader lines, arrows, contours, dimensions и другими protected graphics.

## 3. Figure 2 уточнение

3.1. Figure 2 не принимать и не закреплять как accepted, если хотя бы одна translated callout-рамка имеет внутренний зазор больше 5 px от фактических границ перевода, кроме явно зафиксированного manual-review исключения.

3.2. Figure 2 не принимать и не выдавать как финальную review-версию, если рамка может касаться соответствующей выносной линии без повреждения графики, но фактически не касается её.

3.3. Figure 2 пересобирать только от исходного PDF/source crop. Использование R02/R03/R04/R05/R06 PNG как production source запрещено.
